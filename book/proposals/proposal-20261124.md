## Riemann hypothesis: candidates, strongest first

1. **Coverage (universality).** Voronin (1975): the curve `t ↦ ζ(s + it)`, for `s` in the
   right half of the critical strip, passes as close as you like to any analytic function with
   no zero on a small disc. This is "a squiggly line passes close to every target". Its proof
   rests on Kronecker's theorem: the curve `t ↦ (t log 2, t log 3, t log 5, ...)` wraps a torus
   densely, because the logarithms of the primes have no rational relation (unique
   factorisation). (Corrected 24 Nov 2026: this is not what `Theorem/Coverage.lean` proves. The matching notion in this repository is `COVERS_WITHIN` in `Theorem/Oscillation.lean`.) Bagchi (1981): the Riemann
   hypothesis holds if and only if `ζ` passes close to **itself** again and again in this way.
   So the hypothesis has an exact restatement as a nearness statement about one squiggly curve.
2. **Waves under the primes (the explicit formula).** The count of primes is a smooth line
   plus one wave for each zero of `ζ`: a zero `1/2 + iγ` gives a wave of frequency `γ` in
   `log x`. The hypothesis says every wave has the same growth, `x^(1/2)` (von Koch 1901). The
   repository's sums of waves (chapter 11, `RandomFourier.lean`) are the same object. The
   difference to state: the hypothesis is about amplitude, and the squiggly line theorem holds
   amplitude fixed and varies frequency.
3. **Zeros as crossings.** Hardy's function `Z(t)` is a real squiggly line whose sign changes
   are the zeros on the critical line. The number of zeros up to height `T` grows like
   `(T / 2π) log T`, so the line gets squigglier with height. `Theorem/Oscillation.lean` counts
   crossings.

**First bite in Lean.** Two primes: the curve `t ↦ (t log 2, t log 3)` on the torus comes
within any distance of any point, because `log 2 / log 3` is irrational (`2^a ≠ 3^b`). Read
`Coverage.lean` first and reuse what it has; look in Mathlib for dense orbits of an irrational
rotation before proving anything. Then a notebook: how close the partial Euler product over
the first few primes gets to a chosen target as `t` grows, with the prediction written first.

## P ≠ NP: candidates

1. **Lower bounds by counting squiggles.** The known way to show a small circuit cannot
   compute a function is to find a measure of squiggliness that small circuits lack and the
   function has. Parity is the squiggliest Boolean function: every flipped bit changes it.
   Håstad (1986): circuits of fixed depth need exponentially many gates for parity. Linial,
   Mansour and Nisan (1993): such circuits have almost all of their Fourier weight on low
   frequencies. `Supporting/NetworkShape/DepthSeparation.lean` (Telgarsky) is the same argument
   for networks: count the teeth.
2. **The barrier.** Razborov and Rudich (1997), natural proofs: a measure that is easy to
   compute and that most functions have cannot separate P from NP, if pseudorandom functions
   exist. Random functions are squiggly (`Theorem/RandomFunction.lean`). So the method of this
   repository is the method known not to settle the question. This is the honest connection.
3. **Finding the weights is the hard part.** Blum and Rivest (1992): training a three-unit
   network is NP-complete. Chapter 5 says the loss at the start cannot see the nearness; this
   says how hard the search can be in the worst case.

**First bite in Lean.** Parity of `n` bits as a function of their sum changes value `n` times,
so a one-hidden-layer ReLU network reading the sum needs at least about `n` kinks (reuse
`Oscillation.lean` and `DepthSeparation.lean`), while a deep narrow one needs about `log n`
layers of tents.
